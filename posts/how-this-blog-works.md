这篇文章把整个站点一次讲完：GitHub Pages 的托管原理、免构建的文章渲染管线，以及页面上每一个特效的实现思路。全文对应的所有源码都在 [本站仓库](https://github.com/ChengqianHuang/chengqianhuang.github.io)，加起来不到一千行。

## 一、托管原理：GitHub Pages 到底做了什么

GitHub Pages 本质是一个**免费的静态文件 CDN**：

- 你把 HTML / CSS / JS / 图片推到仓库的 `main` 分支
- GitHub 自动把这些文件原样发布到 `<username>.github.io`
- push 之后约一分钟，全球 CDN 节点同步完成

它**不做任何服务端计算**：没有数据库、没有模板引擎、没有路由。你请求 `post.html?post=blog-v3`，服务器就是把 `post.html` 这个文件原样吐回来，`?` 后面的参数完全由浏览器端 JS 自己解析。

这个约束决定了整个技术方案：既然服务端什么都不干，那"动态"的部分——Markdown 渲染、文章列表、主题记忆——就全部挪到浏览器里做。好处是免构建、零依赖、零成本；代价是渲染逻辑要自己写好，还要考虑降级。

## 二、文章系统：浏览器端的渲染管线

### 存储结构

```
├── index.html          # 首页
├── post.html           # 文章页（壳子，内容由 JS 填充）
├── posts/              # 文章本体，纯 Markdown
│   └── how-this-blog-works.md
├── posts.json          # 文章索引（唯一需要手工维护的清单）
└── *.js                # 各特效独立一个文件
```

文章就是普通的 `.md` 文件，开头一段 front matter 存标题和日期：

```markdown
---
title: 文章标题
date: 2026-09-25
---

正文……
```

### 渲染流程

`post.js` 大约 60 行，走完这五步：

1. **取参数**：从 `location.search` 解析出 `?post=xxx` 里的文件名，用正则 `^([A-Za-z0-9_-]+?)(?:\.md)?$` 校验并自动补全 `.md` 后缀，杜绝 `../` 路径穿越
2. **拉原文**：`fetch('posts/xxx.md')`——Markdown 就是个静态文件，直接 GET
3. **拆 front matter**：一个正则匹配开头两道 `---` 之间的 key: value，剩下的部分是正文
4. **渲染**：[marked](https://github.com/markedjs/marked) 把 Markdown 转成 HTML，塞进 `#content`
5. **高亮**：highlight.js 对 `pre code` 逐块上色

标题和日期经过 `escapeHtml` 再插入，正文由 marked 转义后输出——写文章的人是自己，注入风险可控，但引号尖括号还是老老实实转义。

唯一的坑出在第 1 步：早期版本强制要求参数带 `.md` 后缀，而首页生成的链接没带，于是所有文章链接都报"无效的文章地址"。修复方式就是上面的自动补全——**校验放宽 + 入口收敛**，两头都兼容，比只改一边稳。

### 怎么写新文章

1. 在 `posts/` 下新建 `my-post.md`，写好 front matter
2. 在 `posts.json` 里加一行（列表按时间倒序排）：

```json
{ "title": "文章标题", "date": "2026-09-25", "file": "my-post" }
```

3. `git push`，约一分钟后线上可见

没有数据库，没有后台，发布动作就是一次 `git push`。

## 三、特效实现

### WebGL 极光 shader（首页背景）

裸 WebGL 片元着色器，没有 Three.js：

- 画一个覆盖全屏的三角形，片元着色器里对每个像素算颜色
- 两层 **fbm 噪声**（5 octave 的 value noise 分形叠加）生成流动的极光带，蓝→紫→青按噪声值混合
- 鼠标位置作为 uniform 传入，偏移噪声场，背景就"跟着鼠标流"
- 主题感知：`u_dark` uniform 切换叠加模式，暗色下发光、亮色下淡彩
- 性能：一帧一次 draw call，DPR 上限 2，`visibilitychange` 时停帧

### ASCII 甜甜圈

Hero 区右侧那颗旋转的甜甜圈，致敬经典 [donut.c](https://www.a1k0n.net/2011/07/20/donut-math.html)：

- 环面参数方程逐点计算三维坐标，旋转后投影到 42×18 的字符网格
- **z-buffer** 记录每个格子目前的最近深度，被挡住的点直接丢弃——这就是"3D 遮挡"
- Lambert 光照（法向量点乘光源方向）映射到 `.,-~:;=!*#$@` 十级亮度字符
- y 轴投影乘 0.55 适配字符宽高比，约 20fps
- 暗色主题下加 `text-shadow` 辉光，更像 CRT 终端

### 粒子网络背景

Canvas 固定在 `z-index: -1`、`pointer-events: none`，不拦截任何交互。粒子在画布上漂移，鼠标附近的粒子被轻微吸引，距离内的粒子之间连线、透明度随距离衰减。两个细节值得记：

- 速度加阻尼 `vx *= 0.995`，防止吸引累积导致粒子加速失控
- `visibilitychange` 时停帧省电

### 终端启动序列 + 标题解码

首页 Hero 的 `$ whoami`、`$ ls ./posts` 是逐字敲入的打字机动画，`ls` 的输出从 `posts.json` 动态生成——加文章不用改代码。大标题用 scramble 效果进场：乱码字符池逐帧归位。

### 主题切换：无闪烁的关键

明暗切换最容易翻车的是刷新时的白闪（FOUC）。解法是把设置主题的脚本**内联在 `<head>` 里**，在任何渲染发生之前读 `localStorage` / `prefers-color-scheme` 并设好 `data-theme`。之后所有颜色都走 CSS 变量，粒子等 canvas 特效用 `getComputedStyle` 读当前主题色，切换时同步变色。

### 阅读进度条与彩蛋

文章页顶部 3px 进度条随滚动增长，下滑超过 400px 出现返回顶部按钮。页脚藏着 `↑↑↓↓←→←→BA`——Konami 秘籍输入正确，全屏 Matrix 数字雨 8 秒（纯 canvas，片假名 + 十六进制），控制台同时打印一条绿色消息。

## 四、降级与可访问性

炫技的前提是别把读者搭进去：

- **`prefers-reduced-motion`**：系统开了减弱动态效果，所有动画直接静止、文案直接显示全文
- **WebGL 降级链**：WebGL 不可用 → 回落 2D 粒子；再挂 → 纯色背景。站点照常可读
- **CDN 降级**：highlight.js 加载失败就静默退化为纯文本代码块，文章不受影响
- **零单点故障**：核心内容是 HTML + Markdown，所有特效都是锦上添花的独立脚本，挂掉任何一个页面都完整可读

## 五、总结

| 选择 | 放弃的东西 | 换来的东西 |
|------|-----------|-----------|
| GitHub Pages 免费托管 | 服务端逻辑 | 零成本、push 即部署 |
| 浏览器端渲染 Markdown | 构建工具链 | 写作 = 加一个 .md 文件 |
| 原生 JS 手写特效 | 动画库和框架 | 全站不到 1000 行，完全可控 |

这套架构适合个人博客这种"内容为主、更新频率低"的场景。如果哪天需要全文搜索或评论，再考虑引入客户端方案（如客户端索引 + 第三方评论系统），依然不必引入构建步骤。
